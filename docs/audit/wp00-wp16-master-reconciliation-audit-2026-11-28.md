### 2.1 Evidence semantics

- **PASS** — named scenario executed successfully at the exact source SHA with a recorded job/test result.
- **PARTIAL** — a real source slice exists, but one or more required business paths, controls, UI, dependencies or acceptance conditions remain.
- **NOT IMPLEMENTED** — no canonical runtime source proves the required capability at the audited delivery SHA.
- **NOT RUN** — source/test may exist, but the relevant test or operational proof did not execute.
- **BLOCKED** — an explicit external, legal/professional, dependency or human-only gate prevents that particular activation/action; safe engineering continues.
- **FAIL** — a specific executed test/build/acceptance check failed. Static source findings alone are not called an executed failure.

A candidate-branch PASS is not copied to delivery. A source map, design, mock screen, database table, reference-runtime fixture or package archive is not application acceptance.

## 11. Non-negotiable feature-level best practices

Apply these practices across every WP, not as optional polish:

1. **Server-owned authority:** UI/agent/device request is untrusted; Laravel resolves authenticated identity, tenant, position, scope and authority at execution time.
2. **Tenant + same-tenant scope:** forced RLS is defence-in-depth, not replacement for entity/site/department/warehouse/channel/record scopes on every list, detail, search, aggregate, export, queue and object.
3. **Maker-checker/SoD:** separate requester, author, reviewer, approver, operator, worker, device and system actor. A job title or OWNER/ADMIN role does not imply corporate financial approval.
4. **Effective-dated snapshots:** business transaction pins the exact version of price list, tax rule, product/style, BOM, tech pack, route, SOP, SAM, quality plan, assignment and approval used.
5. **Atomic ledger effects:** order/receipt/issue/dispatch/return/journal/payroll actions use one transactional boundary; failure rolls back or emits a controlled compensating event.
6. **Payload-aware idempotency:** same key + same payload returns the same committed receipt; same key + different payload is rejected, audited and surfaced as a conflict.
7. **Concurrency correctness:** lock or compare-and-set critical stock/payment/payroll/quality/assignment/route rows; test last-unit, competing approvals, duplicate scans and simultaneous transitions.
8. **Append-only records:** posted finance, inventory movement, inspection evidence and audit events are corrected through linked reversal/amendment events, not direct edits or deletes.
9. **Unit/currency correctness:** explicit canonical UOM/convertibility, decimal/money precision, approved FX source, explicit rounding/version and base amounts; never add incompatible quantities or use binary float for money.
10. **Complete source genealogy:** initiative/product revision → material source lot/roll/trim → lay/panel/bundle → operation/worker/machine/route → quality/rework → carton/FG → DC/store/channel sale → return/refund → CAPA/next initiative.
11. **Quality at source:** no hold bypass, stale release, unverified waiver, generic AQL or final-release shortcut; customer/product/process/market-specific versioned control plans.
12. **Accessible operator UX:** actor-specific views, clear next action/authority, keyboard/focus/screen reader/contrast, loading/empty/forbidden/retry/conflict/long-running state. UI visibility is not security.
13. **Document integrity:** file bytes are retained, read back and hashed; malware/classification/quarantine gates precede extraction/import; metadata alone is not proof of storage.
14. **Reliable workers/events:** transaction outbox, leases, worker identity/fencing, backoff, DLQ, inbox dedupe, replay and observable failure. No permanent PROCESSING state.
15. **Governed agents:** allowlisted capabilities, minimum tenant context, source links, preconditions rechecked at run, human approval for material actions, no self-approval, rollback/compensation and model/tool trace.
16. **Provider portability:** no mandatory S3/AI/EDI/payment vendor solely to develop; provider-neutral contracts and optional connectors, local configured storage path, secrets injected outside source.
17. **Measurable operations:** KPIs with numerator/denominator, source transaction/event, effective period and access; no fabricated cause or worker ranking. Good output, quality, rework, safety, capacity and finance reconcile.
18. **Exact source/release:** locked dependencies, clean reproducible source, signed/digested artifact, migration version and same SHA across all checks; staging, restore and UAT prior to production.
